# ことば — iPhone用 定型文コピー管理アプリ

よく使う文章を端末内に保存し、一覧からワンタップでコピーする静的PWAです。Xcode・Apple Developer Program・App Store公開は不要です。**一式をHTTPSで公開し、iPhoneのSafariからホーム画面に追加して使います。**

アプリ利用者のアカウント・ログイン・有料API・月額課金は不要です。公開作業をする人には、GitHub等の無料アカウントが必要です。

## 最初に知っておくこと

- **初回導入にはインターネット接続が必要です。** ホーム画面から起動し、「オフライン利用の準備完了」が出るまでオンラインのままにしてください。
- 会社のMDM設定によって、外部URLへのアクセス、ホーム画面への追加、コピー・貼り付け、ファイル保存が制限される場合があります。制限を回避する機能はありません。導入できない場合は管理者に相談してください。
- 定型文はIndexedDBという端末内の保存領域に保存します。**定型文本体や操作履歴を送信する機能はありません。** iCloud、Google Drive、外部DBとの同期・自動バックアップはありません。
- Webサーバーが配信するのは、HTML・JavaScript・アイコン等のアプリ本体だけです。初回配信や更新確認の通信は発生し、ホスティングサービス側には通常のアクセス記録が残り得ます。GitHub Pagesはセキュリティ目的で訪問者のIPを記録します。
- **端末初期化、Webサイトデータの消去、iOSによる領域の解放などで定型文が失われる可能性があります。** 保持要求が許可されても永久保存は保証されません。
- Safariとホーム画面版で保存領域が分かれる場合があります。**ホーム画面へ追加したあと、そのアイコンから起動して本番の文章を登録してください。**

## 1. ファイルを入手する

1. 納品された `kotoba.zip` をMacに保存します。
2. ZIPをダブルクリックして展開します。
3. `kotoba` フォルダを開き、`index.html`、`styles.css`、`app.js`、`sw.js`、`manifest.webmanifest`、`db.js`、`data.js`、`clibor.js`、`icons` フォルダがあることを確認します。
4. 配置前にファイル名やフォルダ構成を変更しないでください。完成版にはビルド・プログラミング・Node.jsのインストールは必要ありません。

`index.html` のダブルクリックによる `file://` 起動では、正しく動作しません。次のHTTPS公開を行います。

## 2. GitHub Pagesで無料公開する（推奨手順）

会社が許可している場合に使用してください。無料プランでは公開リポジトリを使用するため、**アプリのソースコードは誰でも見られます。** 実際の定型文はリポジトリに含めません。

1. Macのブラウザで [GitHub](https://github.com/) を開き、公開担当者のアカウントでログインします。未作成なら無料アカウントを作ります。
2. 右上の「＋」→「New repository」を選びます。
3. Repository nameに `kotoba` と入力し、**Public** を選びます。「Add a README file」があればオンにし、「Create repository」を押します。
4. 作成したリポジトリの「Code」画面で **Add file → Upload files** を選びます。
5. 展開した `kotoba` フォルダの**中身**をアップロードします。フォルダ自体やZIPだけをアップロードしないでください。`icons` はフォルダごとドラッグします。`tests`、README等も公開して差し支えありません。
6. ページ下の「Commit changes」を押します。リポジトリの一番上の階層に `index.html` があり、`icons` の中にPNGがあることを確認します。バックアップJSONや会社の文章はアップロードしません。
7. リポジトリ上部の **Settings → Pages** を開きます。
8. Build and deploymentのSourceを **Deploy from a branch** にします。
9. Branchを **main**、フォルダを **/(root)** にし、**Save** を押します。
10. 公開処理が完了するまで待ちます。反映に最大10分程度かかる場合があります。Settings → Pagesに表示される **Visit site** から公開URLを開きます。
11. URLは通常 `https://あなたのユーザー名.github.io/kotoba/` です。`github.com` のコード画面のURLとは異なります。**HTTPS** で開けることを確認します。

利用者はこの公開URLを開くだけで、GitHubへのログインは必要ありません。コードや実データの公開範囲について社内規程がある場合は、管理者に配置を依頼してください。

## 3. 会社のiPhoneに導入する

1. 公開URLを、会社で許可されたメール・Teams等でiPhoneへ送ります。この操作をアプリが自動で行うことはありません。
2. iPhoneの**Safari**でURLを開きます。メールやTeams内の埋め込みブラウザが開いた場合は、メニューからSafariで開き直します。
3. Safariの共有メニューを開きます。レイアウトによっては、ページメニュー内に「共有」があります。
4. **ホーム画面に追加**を選択します。見つからない場合は共有メニューを下へスクロールします。
5. 「ウェブアプリとして開く」が表示される場合はオンにし、名前「ことば」を確認して**追加**を押します。
6. Safariをいったん離れ、ホーム画面の**ことばのアイコン**をタップします。
7. インターネット接続を保ったまま、一覧上部に **「オフライン利用の準備完了」** と出ることを確認します。Safari側だけの準備完了では判断しないでください。
8. 次の機内モードテストを実施してから、日常利用を始めます。

推奨対象は **iOS 17以降のSafari** です。実際のiOSバージョン・会社設定による差があるため、配布先の実機で確認してください。プライベートブラウズは継続保存の用途に使用しません。

## 4. 必ず行う機内モードテスト

会社の情報を含まない、次のサンプルで試してください。

```text
  コピー確認用です。

改行・日本語・記号 ★ → & を確認します。
末尾の空白も確認  
```

1. ホーム画面から「ことば」を開きます。
2. 「新規登録」を押し、タイトルを「動作確認」、本文にサンプルを入力して「保存」を押します。
3. アプリスイッチャーでことばを閉じ、ホーム画面のアイコンからもう一度開きます。文章が残っていることを確認します。
4. カードの「コピー」をタップし、「コピーしました」を確認します。Outlook等の**未送信の下書き**へ貼り付け、全文・改行・空白を比較します。送信は不要です。
5. iPhoneを機内モードにします。Wi-Fiが別途オンのままなら、Wi-Fiもオフにします。
6. ことばを完全に閉じ、ホーム画面から起動し直します。
7. 一覧表示、検索、新規登録、編集、コピー、削除ができることを確認します。コピーした内容はOutlook等の下書きへ貼り付けて確認します。
8. オフラインで保存した文章が、再起動後も残ることを確認します。
9. テスト後は接続を戻します。テストデータは確認画面を経て削除できます。

「コピーしました」が出ない場合は「手動でコピー」の画面で本文を長押しし、「すべてを選択」→「コピー」を選択します。会社設定で禁止されている場合は手動操作でも利用できません。「コピーしました」はクリップボードへの書き込み完了を表し、別アプリへの貼り付けを保証する表示ではありません。

## 普段の使い方

| 操作 | 手順 |
| --- | --- |
| 登録 | 下部の「新規登録」→ タイトル・本文・カテゴリ・お気に入りを設定 →「保存」 |
| コピー | 一覧カード右下の「コピー」 |
| 編集・削除 | カードの「編集」→ 修正して「保存」、または下部の「この定型文を削除」 |
| 検索 | タイトル・本文の語句を検索欄へ入力 |
| 絞り込み | 「お気に入り」またはカテゴリの選択欄 |
| 並べ替え | 「更新が新しい順」または「タイトル順」 |
| カテゴリ | 一覧の「カテゴリ管理」から追加・改名・削除。削除したカテゴリの文章は「未分類」に残ります。 |
| 外観 | 右上の設定ボタン → 外観 → 端末に合わせる／ライト／ダーク |

件数の固定上限はありません。保存容量・空きメモリ・端末の性能の範囲で使用します。保存エラー時は編集画面に本文を残し、理由を表示します。エラー表示のまま画面を閉じず、必要な入力内容を控えてください。

## Cliborの定型文を最初に取り込む

Cliborの[公式CSV出力機能](https://chigusa-web.com/clibor-for-mac/apply/advanced3/)に対応しています。**実際の定型文を公開アプリのソースやGitHubに埋め込まないでください。** 一度ファイルを選んで取り込むと、その後は端末内に保存した文章として使えます。

1. MacのCliborで「定型文の編集」を開き、定型文のCSV出力を選びます。クリップボード履歴やデータベース全体は移行対象にしません。
2. CSVを端末内の保存先に保存します。標準のUTF-8が推奨です。WindowsのShift_JISも読み込めます。
3. 会社の端末設定で許された方法で、そのCSVだけをiPhoneの「このiPhone内」に移します。AirDropなどが禁止されている場合は回避しません。iCloudなどへの保存・自動同期はこのアプリには必要ありません。
4. **ホーム画面のことばアイコンから起動**して、設定 →「CliborのCSVを取り込む」でファイルを選びます。
5. 件数と案内を確認し、「既存データと統合」を選んで「取り込む」を押します。同じ内容の再取り込みは重複を省略します。全件置き換えには追加確認があります。
6. 数件をコピーして未送信の下書きへ貼り付け、元のClibor本文と比較します。その後、機内モードでも同じ操作を確認します。
7. CSVは平文で文章を含みます。移行完了後の保管・削除は、利用できる安全な保存先と社内規程に合わせて手動で行ってください。アプリは元ファイルを削除しません。

対応する日本語ヘッダは `定型文,メモ,ホットキー`（3列）、または `定型文グループ,定型文,メモ,ホットキー`（4列）です。グループ名を省いた3列形式は「未分類」として取り込みます。英語版の `Template Text,Notes,Hotkeys` とグループ列付きにも対応します。引用符で囲まれたカンマ・改行・二重引用符も処理し、本文は変換しません。空本文や80文字を超えるグループ名など、不正なレコードが一つでもあれば全件を取り込まず、既存データを保持します。

グループはカテゴリに、メモの最初の空白でない行はタイトルになります。メモがなければ本文の最初の空白でない行を使い、タイトルは200文字以内に整えます。**元メモ全文と元ホットキーは編集画面の「Cliborの元メモ」に保存され、JSONバックアップにも含まれます。** ホットキーはiPhone上では動作しません。Cliborのマクロは文字列のまま残り、実行・展開されません。お気に入りは移行時にはオフです。

CSVの読み込み・確認・保存はオフラインでも可能です。初回起動時の自動読み込みや外部サーバーからの定型文取得は行いません。

## 手動バックアップと復元

バックアップを作らなくても通常機能は利用できます。会社がファイル書き出しを禁止している場合は使わないでください。

### 書き出し

1. 会社が許可する場合に限り、Safariのダウンロード先を確認します。最近のiOSでは **設定アプリ → アプリ → Safari → ダウンロード → このiPhone内** です。古いiOSでは設定直下のSafariから開きます。管理されている設定は変更せず、管理者に確認します。
2. ことばの設定 →「JSONファイルを書き出す」を押します。
3. 保存先の案内を読み、「書き出す」を押します。
4. 「ファイル」アプリで `kotoba-backup-年-月-日.json` が保存されたことを確認します。Safariの表示によってはプレビューから保存先を選びます。**iCloud Drive、Google Driveなどのクラウド保存先は選ばないでください。**

ファイルには全定型文の本文が含まれ、暗号化されていません。アクセスを許可された人だけが扱うようにしてください。「書き出す」の操作だけではファイル保存完了を確認できないため、アプリは保存成功と断定しません。OSの保存先・共有先をWebアプリから固定することはできません。

### 復元

1. 設定 →「JSONファイルから復元する」→ バックアップファイルを選びます。
2. 内容が検証され、定型文・カテゴリの件数が表示されます。
3. **既存データと統合** または **すべて置き換え** を選びます。
4. 「復元する」を押します。置き換えには追加の確認があります。

統合ではカテゴリ名が同じならまとめます。タイトル・本文・対応カテゴリ・お気に入りが同一の定型文は、IDや日時が異なっても重複を省略します。同じIDで本文等が変わっていれば、既存文章を残し、別の定型文として追加します。完全一致の重複カードを意図的に残したい場合は「置き換え」を使用します。

置き換えは現在の定型文・カテゴリをすべて置き換えます。外観設定は保持します。空のバックアップを選ぶと0件になります。不正JSON・未知の形式・重複ID・不正なカテゴリ参照等は**保存前**に拒否します。復元途中の保存失敗では、全変更を取り消して元データを残します。

20 MBを超えるファイルはメモリ負荷について確認してから読み込みます。件数で拒否する制限はありませんが、端末のメモリを超えるファイルは取り込めません。

## アプリの更新・オフライン準備

- 設定の「アプリの更新・準備を確認」で更新確認と欠損キャッシュの修復を行えます。オンラインで実行してください。
- 更新版の準備ができても入力中の画面は強制的に再読み込みしません。保存を終え、Safariを含めてことばを開いている全画面を閉じ、ホーム画面から開き直します。
- 更新ファイルが不足・破損している場合は、旧バージョンの正常なキャッシュを保持します。IndexedDBの定型文はアプリ用キャッシュとは別です。
- 保存データを消す目的以外で、Safariの「履歴とWebサイトデータを消去」を使用しないでください。
- 公開URLのドメインや配置フォルダを変えると別の保存領域になります。移転する場合は、会社が許可した手動バックアップ・復元で移行します。

## うまく動かないとき

| 状況 | 確認すること |
| --- | --- |
| ホーム画面に追加がない | Safariで開いているか確認。会社の制限の場合は管理者へ相談。 |
| 公開URLが404 | Pagesの公開完了を待つ。`index.html` が公開元の直下か確認。URL末尾の `/` を含めて開く。 |
| オフライン準備が終わらない | HTTPS・ネット接続・アイコン等のアップロード漏れを確認。設定から再確認。初回準備中はアプリを閉じない。 |
| 更新後に準備エラー | 全ファイルを同じリリースで配置したか確認。改変した場合は技術資料のハッシュ再生成が必要。 |
| 保存できない | 表示されたエラーを確認。入力を控え、端末の空き容量・通常ブラウズ・MDM設定を確認。 |
| コピーできない | 手動選択を利用。管理対象アプリへの貼り付け制限は管理者へ相談。 |
| 以前の文章がない | 同じホーム画面アイコン・同じ公開URLで起動しているか確認。Safari側や別URLのデータは自動共有しない。 |
| バックアップが書き出せない | 通常利用は継続可能。会社のファイル保存規程に従う。 |

管理者が外部サービスを許可していない場合、会社が管理するHTTPS静的サーバーに同じファイル一式を配置する方法があります。必要なのはファイル配信だけです。MDM解除、証明書警告の無視、禁止されたアプリ間転送は行いません。

kotoba/
├── index.html                 画面・設定・入力フォーム
├── styles.css                 日本語UI・ダークモード・セーフエリア
├── app.js                     一覧・編集・コピー・バックアップ・状態表示

├── sw.js                      オフライン・更新・整合性チェック

├── icons/                     SVG、PNG、起動画面
├── .nojekyll                  GitHub Pagesの静的配信用
├── package.json               開発者用テスト設定（運用時には不要）
├── README.md                  この導入ガイド
├── TESTING.md                 テスト結果とiPhone確認表
├── TECHNICAL.md               更新・実装・制約の技術資料

実施済みのテスト結果と、実機で行う確認項目は [TESTING.md](./TESTING.md) に記載しています。**iPhone実機・会社MDM・実際のOutlook等への貼り付けはこの環境では未検証です。**
